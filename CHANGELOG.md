# История изменений

## 0.2.0 — 15 ноября 2026

Безопасность: выполнен раздел 1 дорожной карты («Срочные правки безопасности»). Протокол между приложениями изменён, клиенты и главные 0.1.x с 0.2.0 несовместимы — обновите все устройства.

### Защищённый канал и доверие

- TLS 1.2 между приложениями: Windows-хост защищает LAN-мост, Android-хост — LAN-листенеры. Локальное окно чата на главном остаётся на loopback-канале.
- Самоподписанный сертификат главного (RSA-2048, CN=Ryadom Host, 5 лет) и TOFU-закрепление отпечатка SHA-256 на клиенте при первом подключении. При смене сертификата подключение отклоняется с понятной ошибкой; на Android есть «Сбросить доверие для этого адреса», на Windows — удаление `%LOCALAPPDATA%\Ryadom\tls-pins.txt`.
- Браузерный доступ к главному по локальному адресу в 0.2.0 отключён: браузер не может закрепить самоподписанный сертификат, а незашифрованный канал оставлять небезопасно. Подключение — только приложениями Рядом для Windows и Android.

### Сессии и подключение устройств

- Сессии главного и клиентов — случайные токены (в хранилище только SHA-256), срок 30 дней, отзыв при выходе, «Выйти на всех устройствах», отзыв сессий при удалении устройства. Детерминированный токен главного из 0.1.x удалён.
- Вход главного в окно чата — по одноразовому токену (120 с), который выдаёт native-оболочка; постоянный ключ больше не передаётся в командной строке/URL. Служебные `/api/local/*` требуют native-ключ.
- Спаривание: код одноразовый (ротация при запросе), новое устройство появляется у главного как запрос на подтверждение, клиент ждёт решения и получает сессию только после одобрения; отклонение/истечение показывает ошибку.
- На главном — журнал подключений и отказов (последние 50 событий), лимит ожидающих запросов и частоты попыток.

### Устойчивость и квоты

- Android: таймауты чтения заголовков (10 с) и тела (60 с), лимиты соединений на IP (16) и всего (128), SSE вынесен из рабочего пула (8 стримов на устройство, очередь 256 событий с отключением медленного клиента), рассылка сообщений не блокирует общее состояние.
- Windows: idle-таймаут моста 120 с, лимиты 16 соединений на IP и 256 всего.
- Квоты и лимиты: общий объём хранилища 20 ГБ и 8 ГБ на устройство (настраиваются), проверка свободного места, 120 сообщений/мин и 30 передач/мин на устройство. При превышении — понятные ошибки 429/507; автоматического удаления файлов нет.

### Брандмауэр Windows

- Правила создаются только для частных сетей (Private/Domain) и локальной подсети; для «Общедоступной» сети показывается предупреждение и инструкция сменить профиль.
- Диагностика проверяет оба правила (TCP и UDP), включённость, направление, действие, путь приложения, порт и ограничение удалённых адресов; ложное «правила есть» устранено.
- Установка атомарная: сначала создаются временные правила и проверяются, только потом заменяются старые; при ошибке старые правила не удаляются. Повторная настройка — из меню значка.
- Сторонний брандмауэр (ESET, Kaspersky) показывается как факт установки, а не как доказанная причина блокировки; подсказка предлагает проверить его правила.

### Совместимость и известные ограничения

- Windows 0.2.0.0; Android `versionName` 0.2.0, `versionCode` 5 (устанавливается поверх 0.1.2, ключ подписи прежний); API/сервер 0.2.0.
- Клиенты/главные 0.1.x несовместимы: соединение не установится (другой протокол и TLS). Обновите все устройства.
- iOS-приложения нет; браузерный доступ в 0.2.0 не поддерживается.
- Сертификат самоподписанный: доверие основано на отпечатке; после переустановки/очистки данных главного клиентам нужен сброс доверия.
- Подтверждение подключения требует, чтобы главное устройство было открыто; запрос действует 2 минуты.
- Тесты: Node-хост 23/23, Android-хост на JVM 24/24 (включая security и TLS), Windows transport/TLS — PASS. Реальный Android/эмулятор и живая связка Windows↔Android не проверялись.
- Ограничения квот: лимиты задаются переменными окружения; автоочистки нет — при заполнении новые передачи отклоняются.

### Подпись

- Артефакты 0.2.0 подписываются существующей инфраструктурой: Authenticode для EXE (самоподписанный сертификат до покупки OV/EV) и отделённая подпись OpenSSH манифеста `SHA256SUMS.txt`. Ключ APK хранится вне OneDrive, релизная сборка без ключа останавливается.

## 0.1.2 — 7 ноября 2026

Исправлена ошибка подключения, когда главным устройством выбран Windows-ПК: телефон не мог установить TCP-соединение и показывал `failed to connect to /192.168.1.38 (port 4280) … after 4500ms`, хотя поиск в сети, интернет и пинг в локальной сети работали. Причина — входящие подключения к `Ryadom-Windows.exe` фильтровал брандмауэр: при выключенном брандмауэре Windows это оказался сторонний брандмауэр (ESET), а правила для приложения отсутствовали. Happ, кабель и роутер к ошибке отношения не имели.

**Windows**

- Новый модуль `windows/Firewall.cs`: определяет активные сторонние брандмауэры через `root\SecurityCenter2`, состояние профилей брандмауэра Windows, наличие входящих правил для приложения и профиль домашней сети (общедоступная/частная). Устаревшие записи Security Center без установленного продукта игнорируются.
- При первом запуске в режиме главного устройства приложение один раз на сборку показывает подсказку:
  - если активен сторонний брандмауэр — название продукта, порты TCP 4280 (чат) и UDP 42800 (поиск), где добавить правило, и предупреждение, что правила брандмауэра Windows при этом не действуют;
  - если включён брандмауэр Windows — предложение добавить входящие правила для `Ryadom-Windows.exe` только из локальной сети (один запрос UAC; правила `Ryadom chat TCP 4280` и `Ryadom discovery UDP 42800`).
- В меню значка Рядом добавлен пункт **«Проверить брандмауэр и сеть»** с текущим отчётом и подсказкой.
- Диагностический режим: `Ryadom-Windows.exe --firewall-check <файл-отчёта>`.
- Учитывается только профиль брандмауэра, применённый к домашней сети: включённый Domain-профиль на другом интерфейсе больше не даёт ложного вывода «брандмауэр Windows включён».
- Номер сборки Windows: 0.1.2.

**Android**

- Текст ошибки подключения теперь прямо говорит про входящие TCP 4280 и UDP 42800 на главном устройстве и сторонний брандмауэр (ESET, Kaspersky). `versionName` 0.1.2, `versionCode` 4 (устанавливается поверх 0.1).

**Документация**

- `docs/GUIDE.md`: новый раздел «Брандмауэр на главном Windows-ПК» — брандмауэр Windows, сторонние ESET/Kaspersky, «Доверенная сеть», смена профиля сети на «Частная», быстрая проверка `http://адрес:4280/api/health`.
- README: подсказка про брандмауэр в возможностях и обновлённые ссылки на выпуск 0.1.2.
- Версии интерфейса и сервера обновлены до 0.1.2.

## 0.1

Первый выпуск с утверждённым номером версии. Ранее подготовленные локальные сборки с обозначением 2.0 переименованы в 0.1 без удаления возможностей.

- Личный чат для текста, фото, видео и файлов до 512 МБ в одной домашней сети.
- Приложения для Windows 10/11 x64 и Android 8.0+.
- Выбор главного устройства при запуске и возможность изменить выбор.
- Главным устройством может быть Windows-ПК или Android-телефон.
- Поддержка Ethernet и Wi-Fi в одной локальной подсети.
- Поиск главного устройства и подключение по адресу и коду.
- Прямое подключение через физическую домашнюю сеть при работающем VPN, если системные правила разрешают обход; инструкция для Happ.
- История и оригиналы файлов хранятся на выбранном главном устройстве.

APK использует прежний ключ подписи и увеличенный внутренний номер сборки, поэтому устанавливается поверх предыдущей локальной сборки, несмотря на меньший отображаемый номер версии.

### Проверка и ограничения

Серверы и прямые шлюзы проверены автоматическими тестами. На Windows проверен Ethernet при включённом Happ. APK собран и подписан; на физическом Android и между двумя отдельными устройствами пока не проверен.

Автоматического переноса истории между главными устройствами нет. Изоляция клиентов роутером, брандмауэр и запрет соединений вне VPN могут препятствовать связи. Передача внутри доверенной локальной сети идёт без TLS и сквозного шифрования.
