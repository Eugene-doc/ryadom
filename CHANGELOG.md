## 0.4.0 — 21 ноября 2026

Эфемерный общий чат и постоянная идентичность устройств. Протокол 4; Android `versionCode 12`, Windows `0.4.0.0`.

**Подробные примечания и файлы выпуска:** [docs/releases/0.4.0.md](docs/releases/0.4.0.md).

- **Один общий чат.** История принадлежит текущей сессии главного; при его штатном завершении, выходе из роли или аварии она очищается у всех. Настройки, TLS, identity и доверенные устройства сохраняются.
- **Постоянные устройства.** `d1-*` identity, device token, `/api/auth` и roster позволяют знакомому устройству подключаться без нового кода и после смены главного.
- **Главный по identity.** Discovery V2 передаёт `hostId`/TLS fingerprint; Windows и Android запоминают их и сверяют при подключении; IP остаётся маршрутом.
- **Отзыв устройств.** Отозванные ID попадают в roster, удаляются у нового главного при импорте и не могут повторно подключиться по старой identity.
- **Protocol 4 gate.** `/api/pair` и `/api/auth` требуют protocol 4; клиенты 0.3.x получают 426.
- **Надёжность.** Fail-closed очистка при старте, отмена загрузок при shutdown, Android crash-marker, sessionId-reset, host ID migration.
- **Проверки.** Node 42/42; Android 40/40; Windows transport/TLS/discovery/firewall PASS.
- **Ограничение.** Identity — TLS-защищённый bearer-токен, не CNG/Keystore keypair; roster/discovery не подписаны. Это зафиксировано в примечаниях.

## 0.3.2 — 19 ноября 2026

Срочный патч входящих подключений Windows. Протокол 3; Android `versionCode 10`, Windows `0.3.2.0`.

**Подробные примечания и файлы выпуска:** [docs/releases/0.3.2.md](docs/releases/0.3.2.md).

- **Причина «ноутбук не подключается к ПК».** На проблемном ПК сеть была Public, активен ESET Firewall; Windows Firewall Public/Private выключен, правила Рядом отсутствовали. Исходящие соединения работали, входящий TCP 4280 блокировался до приложения. Это не TLS-ошибка.
- **Диагностика.** Отчёт показывает локальные адреса, категорию сети, профили Windows Firewall, активный сторонний брандмауэр и отсутствие правил; устаревшие записи Kaspersky отфильтровываются.
- **Действия.** Приложение предлагает переключить домашнюю сеть в «Частную» через UAC, установить правила Windows и открыть ESET с точными параметрами TCP 4280 / UDP 42800.
- **Ошибка подключения** теперь подсказывает проверить входящие порты, профиль сети и ESET/Happ.
- **Self-check** усилен: локальный адрес определяется через DNS и несколько сетевых API.

## 0.3.1 — 16 ноября 2026

Срочный патч: self-discovery/self-connect, проверка сертификата при первом входе и порядок в списке устройств. Протокол 3; Android `versionCode 9`, Windows `0.3.1.0`.

**Подробные примечания и файлы выпуска:** [docs/releases/0.3.1.md](docs/releases/0.3.1.md).

- **Своё устройство больше не предлагается как главное.** Windows и Android фильтруют собственные адреса из discovery и отклоняют подключение к себе с понятным сообщением. Это устраняет ложное «Нет ответа», когда устройство пыталось соединиться со своим же IP, пока другие устройства успешно подключались к нему как к главному.
- **Проверка сертификата при первом входе.** Вместо молчаливого TOFU показывается SHA-256 отпечаток и запрос на доверие; при смене сертификата предлагается сбросить доверие только для этого адреса.
- **Список устройств.** Добавлена последняя активность и сортировка; при переходе в роль главного старый `last-target` удаляется, чтобы не подставлять прошлое подключение. На главном можно забыть неактивные устройства.
- **История.** В настройках явно указано, что при смене главного открывается история нового главного и автоматического переноса нет.
- **Проверки.** Node 39/39; Android JVM + Java-host; Windows self-address/pin/TLS/firewall PASS.

## 0.3.0 — 16 ноября 2026

Функциональное обновление: управление историей, загрузки, версия и собственная Windows-оболочка. Протокол 3; Android `versionCode 8`, Windows `0.3.0.0`.

**Подробные примечания и файлы выпуска:** [docs/releases/0.3.0.md](docs/releases/0.3.0.md).

- **Удаление сообщений.** Автор удаляет своё сообщение, главный — любое; подтверждение, удаление у всех подключённых, удаление связанного вложения. Удалённые записи остаются tombstone-строками без текста/файла, поэтому повтор с тем же `requestId` не воскрешает сообщение.
- **Очистка чата.** Главный видит предпросмотр (сообщения, файлы, байты, незавершённые передачи), подтверждает операцию с проверкой ревизии; очистка отменяет активные загрузки, удаляет файлы и `.part`, освобождает квоту, пишет журнал операции. Ошибки unlink не скрываются: операция получает `partial`, файл остаётся в состоянии `deleting` до повторной очистки при следующем запуске. Внешние копии, которые пользователь уже сохранил, не удаляются.
- **Загрузки.** В Windows-окне кнопка «Открыть загрузки» открывает `%USERPROFILE%\Downloads\Рядом` (последний файл выделяется); WebView2 перехватывает скачивания в эту папку. На Android кнопка показывает сохранённые через Рядом файлы и открывает их через SAF/FileProvider.
- **Windows-оболочка.** Вместо окна Edge — собственное WinForms-окно с WebView2, иконкой Рядом и AppUserModelID; меню «Создать ярлык на рабочем столе» и инструкция по закреплению. WebView2 Runtime обязателен для собственного окна; при его отсутствии открывается запасной Edge с предупреждением. SDK фиксированной версии встроен в EXE, `WebView2Loader.dll` извлекается в `%LOCALAPPDATA%\Ryadom\webview2`.
- **Версия при запуске.** Версия показывается в окне выбора роли, в панели Windows-окна и в настройках Android/веб-интерфейса; сервер и клиент показываются отдельно.
- **Протокол 3 и миграция.** SQLite/JSON получают `chat.id=legacy`, `revision`, `epoch`, `deletedAt/deletedBy`, `files.messageId/state`, `operations`; миграция идемпотентна, история 0.2.x сохраняется. Старые клиенты 0.2.x следует обновить: протокол 3 и новые события удаления/очистки.
- **Проверки.** Node 39/39; Android JVM + Java-host контракт зелёный (включая FunctionalTest и рестарт с восстановлением); Windows transport/TLS/firewall PASS; WebView2-окно проверено отдельным harness (окно открывается, msedgewebview2 запускается). Реальный Android и полная матрица Windows 10/11 не проверялись.
- **Ревью Codex.** Первый проход: 5 High, 8 Medium, 3 Low; исправлены гонки revision/epoch, конкурентная очистка, восстановление `deleting`, коллизии загрузок, устаревшие ответы UI, Windows fallback. Повторная проверка исправлений: 3 High (поздний clear-ответ, порядок SSE, load-older) и 2 Medium (повтор operationId, повторная навигация WebView2) — исправлены в `47e12dd`+. Финальный внешний проход после этих правок не запускался (бюджет делегаций исчерпан); исправления подтверждены тестами и чтением кода.

## 0.2.2 — 15 ноября 2026 (Android)

Срочное исправление работы при активном Happ/VPN. Версия для Windows и серверная часть не менялись (0.2.1), протокол 2.

- **Хост при активном VPN.** Глобальная привязка процесса к Wi-Fi убрана: она не нужна LAN-листенерам и могла наследоваться клиентскими сокетами после смены роли. Чат на телефоне запускается при активном Happ/VPN; LAN-листенеры привязываются к адресам Wi-Fi/Ethernet.
- **Клиент при ошибке 316.** Сокет создаётся вручную и привязывается через `Network.bindSocket`; при `EPERM`/`SecurityException` он гарантированно закрывается, после чего подключение повторяется обычным несвязанным сокетом по системному маршруту. Это позволяет работать, когда Happ отправляет локальные адреса напрямую (LAN Direct), и не оставляет дескрипторы в старом Android.
- **Discovery.** Привязка UDP-сокетов к сети стала необязательной; ошибки broadcast/multicast и отдельных интерфейсов больше не обрывают весь поиск, ответы принимаются, если отправка хотя бы одного пакета удалась. Ошибка полного отказа поиска возвращается в интерфейс, повреждённый ответ не прекращает приём.
- **Устойчивость Android-хоста.** Листенер и принятый сокет закрываются, если их настройка не удалась; discovery не крутится в busy-loop при постоянной ошибке `receive`.
- **Сообщения.** При активном VPN ошибка теперь прямо объясняет ограничение Android и просит включить в Happ маршрут локальной сети напрямую или исключить «Рядом»; приложение не может принудительно обойти чужой `VpnService`.
- **Версия Android:** `versionCode 7`, `versionName 0.2.2`; подпись прежним ключом. APK собран, JVM-тесты — 27/27, добавлен тест классификации `EPERM`. Проверка на реальном телефоне с Happ не выполнялась.

## 0.2.1 — 15 ноября 2026

Исправления по независимому ревью Codex релиза 0.2.0: Critical не найдено, исправлены 5 High, 4 Medium и 1 Low. Протокол не менялся (2), клиенты 0.2.0 совместимы.

### High

- **SSE отзывается вместе с сессией.** Поток привязан к хешу сессии и сроку; logout, «выйти на всех», отзыв устройства и истечение TTL закрывают соответствующие потоки (Node и Android). Регистрация потока на Android синхронизирована с проверкой/отзывом доступа, окно «проверка прошла → устройство отозвали → поток зарегистрировался» закрыто. Добавлены тесты.
- **Android: миграция старых сессий один раз.** В состоянии появилась `schema=2`; legacy `devices.token` переносится и удаляется атомарно, при повторном старте миграция не выполняется. Отозванные старые токены больше не воскресают после перезапуска.
- **Windows: таймаут TLS-рукопожатия.** `SslStream` handshake ограничен абсолютным сроком (по умолчанию 10 с, настраивается), сокет закрывается при превышении. Клиент, который подключился и молчит, больше не занимает слот до 120 с.
- **Android: абсолютные дедлайны запросов.** Ограничен общий срок заголовков (10 с) и тела (60 с без прогресса + 30 мин абсолютный максимум); медленная побайтовая подача не продлевает соединение. Значения настраиваются env.
- **Атомарные резервы квот.** Объявленный размер загрузки резервируется глобально и по устройству до начала передачи, учитывается в проверках свободного места и перепроверяется при фиксации; резерв освобождается в `finally` (Node и Android). Параллельные загрузки больше не обходят лимиты.

### Medium / Low

- Windows: ошибка чтения или записи TOFU-хранилища теперь отклоняет соединение (раньше принимался новый сертификат); запись pin атомарная, под блокировкой.
- Брандмауэр: исправлен разбор вывода PowerShell (буквальный `` `t `` вместо табуляции); проверяются точный набор профилей Private/Domain и адресов LocalSubnet; установка сохраняет старые правила в backup, проверяет результат каждого шага, откатывается при ошибке и проверяет exit code. Добавлен тест парсера.
- `choose-role`: сессия главного разрешена для браузерной кнопки; клиентский прокси больше не позволяет менять роль без аутентификации — смена роли клиента остаётся в нативном интерфейсе (меню значка Windows, панель Android). Кнопка у клиента скрыта.
- Android публикует адрес как `http://IP:port`; Windows RolePicker принимает `http` и `https`, адрес без схемы. Транспорт по-прежнему TLS.
- Версии: 0.2.1, Windows `0.2.1.0`, Android `versionCode 6`, протокол 2.

### Проверки

- Node-хост: 26/26 (`server`, `security`, `proxy`), включая новые тесты SSE-отзыва, параллельных квот и `choose-role`.
- Android-хост на JVM: 27/27 (`server`, `security`, `proxy`) + JVM-тесты сертификата/TOFU, SSE/миграции, дедлайнов и квот.
- Windows: transport, discovery, TLS-мост с пиннингом, handshake-deadline, отказ при ошибке pin-хранилища, смена сертификата, парсер брандмауэра — PASS.
- Ревью Codex выполнено 4-й попыткой (CLI 0.169, с разрешения пользователя): 1 591 474 токена, 598,7 с. Повторное ревью после исправлений не проводилось.
- Не проверено: реальный Android/эмулятор, живая связка Windows↔Android, установка правил брандмауэра вживую (нужен UAC).

## 0.2.0 — 15 ноября 2026

Безопасность: выполнен раздел 1 дорожной карты («Срочные правки безопасности»). Протокол между приложениями изменён, клиенты и главные 0.1.x с 0.2.0 несовместимы — обновите все устройства.

### Защищённый канал и доверие

- TLS 1.2 между приложениями: Windows-хост защищает LAN-мост, Android-хост — LAN-листенеры. Локальное окно чата на главном остаётся на loopback-канале.
- Самоподписанный сертификат главного (RSA-2048, CN=Ryadom Host, 5 лет) и TOFU-закрепление отпечатка SHA-256 на клиенте при первом подключении. При смене сертификата подключение отклоняется с понятной ошибкой; на Android есть «Сбросить доверие для этого адреса», на Windows — удаление `%LOCALAPPDATA%\Ryadom\tls-pins.txt`.
- Браузерный доступ к главному по локальному адресу в 0.2.0 отключён: браузер не может закрепить самоподписанный сертификат, а незашифрованный канал оставлять небезопасно. Подключение — только приложениями Рядом для Windows и Android.

### Сессии и подключение устройств

- Сессии главного и клиентов — случайные токены (в хранилище только SHA-256), срок 30 дней, отзыв при выходе, «Выйти на всех устройствах», отзыв сессий при удалении устройства. Детерминированный токен главного из 0.1.x удалён.
- Вход главного в окно чата — по одноразовому токену (120 с), который выдаёт native-оболочка; постоянный ключ больше не передаётся в командной строке/URL. Служебные `/api/local/*` требуют native-ключ.
- Спаривание: код одноразовый (ротация при запросе), новое устройство появляется у главного как запрос на подтверждение, клиент ждёт решения и получает сессию только после одобрения; отклонение/истечение показывает ошибку.
- На главном — журнал подключений и отказов (последние 50 событий), лимит ожидающих запросов и частоты попыток.

### Устойчивость и квоты

- Android: таймауты чтения заголовков (10 с) и тела (60 с), лимиты соединений на IP (16) и всего (128), SSE вынесен из рабочего пула (8 стримов на устройство, очередь 256 событий с отключением медленного клиента), рассылка сообщений не блокирует общее состояние.
- Windows: idle-таймаут моста 120 с, лимиты 16 соединений на IP и 256 всего.
- Квоты и лимиты: общий объём хранилища 20 ГБ и 8 ГБ на устройство (настраиваются), проверка свободного места, 120 сообщений/мин и 30 передач/мин на устройство. При превышении — понятные ошибки 429/507; автоматического удаления файлов нет.

### Брандмауэр Windows

- Правила создаются только для частных сетей (Private/Domain) и локальной подсети; для «Общедоступной» сети показывается предупреждение и инструкция сменить профиль.
- Диагностика проверяет оба правила (TCP и UDP), включённость, направление, действие, путь приложения, порт и ограничение удалённых адресов; ложное «правила есть» устранено.
- Установка атомарная: сначала создаются временные правила и проверяются, только потом заменяются старые; при ошибке старые правила не удаляются. Повторная настройка — из меню значка.
- Сторонний брандмауэр (ESET, Kaspersky) показывается как факт установки, а не как доказанная причина блокировки; подсказка предлагает проверить его правила.

### Совместимость и известные ограничения

## 0.1.2 — 7 ноября 2026

Исправлена ошибка подключения, когда главным устройством выбран Windows-ПК: телефон не мог установить TCP-соединение и показывал `failed to connect to /192.168.1.38 (port 4280) … after 4500ms`, хотя поиск в сети, интернет и пинг в локальной сети работали. Причина — входящие подключения к `Ryadom-Windows.exe` фильтровал брандмауэр: при выключенном брандмауэре Windows это оказался сторонний брандмауэр (ESET), а правила для приложения отсутствовали. Happ, кабель и роутер к ошибке отношения не имели.

**Windows**

- Новый модуль `windows/Firewall.cs`: определяет активные сторонние брандмауэры через `root\SecurityCenter2`, состояние профилей брандмауэра Windows, наличие входящих правил для приложения и профиль домашней сети (общедоступная/частная). Устаревшие записи Security Center без установленного продукта игнорируются.
- При первом запуске в режиме главного устройства приложение один раз на сборку показывает подсказку:
  - если активен сторонний брандмауэр — название продукта, порты TCP 4280 (чат) и UDP 42800 (поиск), где добавить правило, и предупреждение, что правила брандмауэра Windows при этом не действуют;
  - если включён брандмауэр Windows — предложение добавить входящие правила для `Ryadom-Windows.exe` только из локальной сети (один запрос UAC; правила `Ryadom chat TCP 4280` и `Ryadom discovery UDP 42800`).
- В меню значка Рядом добавлен пункт **«Проверить брандмауэр и сеть»** с текущим отчётом и подсказкой.
- Диагностический режим: `Ryadom-Windows.exe --firewall-check <файл-отчёта>`.
- Учитывается только профиль брандмауэра, применённый к домашней сети: включённый Domain-профиль на другом интерфейсе больше не даёт ложного вывода «брандмауэр Windows включён».
- Номер сборки Windows: 0.1.2.

**Android**

- Текст ошибки подключения теперь прямо говорит про входящие TCP 4280 и UDP 42800 на главном устройстве и сторонний брандмауэр (ESET, Kaspersky). `versionName` 0.1.2, `versionCode` 4 (устанавливается поверх 0.1).

## 0.1

Первый выпуск с утверждённым номером версии. Ранее подготовленные локальные сборки с обозначением 2.0 переименованы в 0.1 без удаления возможностей.

- Личный чат для текста, фото, видео и файлов до 512 МБ в одной домашней сети.
- Приложения для Windows 10/11 x64 и Android 8.0+.
- Выбор главного устройства при запуске и возможность изменить выбор.
- Главным устройством может быть Windows-ПК или Android-телефон.
- Поддержка Ethernet и Wi-Fi в одной локальной подсети.
- Поиск главного устройства и подключение по адресу и коду.
- Прямое подключение через физическую домашнюю сеть при работающем VPN, если системные правила разрешают обход; инструкция для Happ.
- История и оригиналы файлов хранятся на выбранном главном устройстве.

APK использует прежний ключ подписи и увеличенный внутренний номер сборки, поэтому устанавливается поверх предыдущей локальной сборки, несмотря на меньший отображаемый номер версии.

### Проверка и ограничения

Серверы и прямые шлюзы проверены автоматическими тестами. На Windows проверен Ethernet при включённом Happ. APK собран и подписан; на физическом Android и между двумя отдельными устройствами пока не проверен.

Автоматического переноса истории между главными устройствами нет. Изоляция клиентов роутером, брандмауэр и запрет соединений вне VPN могут препятствовать связи. Передача внутри доверенной локальной сети идёт без TLS и сквозного шифрования.
