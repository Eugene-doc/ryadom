# Рядом 0.4.0 — эфемерный чат и постоянные устройства

**Дата:** 21.11.2026  
**Статус:** выпущен  
**Тег:** `v0.4.0`  
**GitHub Release:** https://github.com/Eugene-doc/ryadom/releases/tag/v0.4.0

## Главное

- **Один общий чат на время сессии.** История принадлежит текущей сессии главного, а не устройству: все подключённые устройства видят одни и те же сообщения.
- **История очищается при завершении главного.** Штатное выключение, выход из роли и аварийное завершение очищают сообщения, вложения и временные файлы у всех; настройки, TLS, идентичности и доверенные устройства остаются.
- **Устройства запоминаются.** Постоянный `deviceId`, device token и roster позволяют знакомому устройству подключиться без нового кода, в том числе после смены главного, если roster был сохранён.
- **Главный запоминается по identity, а не по IP.** Discovery V2 передаёт `hostId` и TLS fingerprint; Windows/Android сохраняют их и используют при повторном поиске.
- **Протокол 4.** Клиенты 0.3.x несовместимы; при подключении они получают требование обновиться.

## Что меняется для пользователя

- После выключения главного следующий запуск начинает **пустой чат**. Это ожидаемое поведение, а не потеря синхронизации.
- При смене главного старый чат завершается; новый главный начинает новую пустую сессию. История не переносится.
- Устройство, которое уже подключалось, может восстановить доступ по своей identity; если его запись отозвана, потребуется новое подключение по коду.
- Roster доверенных устройств сохраняется локально на каждом устройстве и обновляется при изменениях на главном.
- Отозванные устройства не возвращаются при импорте roster и не могут повторно подключиться по старому ID.

## Совместимость и обновление

- Протокол: **4**.
- Windows: **0.4.0.0**, Windows 10/11 x64, WebView2 Runtime.
- Android: **0.4.0**, `versionCode 12`; устанавливать поверх 0.3.3.
- Обновить **все** устройства. Клиенты 0.3.x получают 426 и должны быть обновлены.
- При первом запуске 0.4.0 предыдущая история 0.3.x очищается в соответствии с новой эфемерной моделью. Старые устройства/сессии сохраняются, но старые bearer-токены не использовались для v4-auth; при необходимости устройство подключается по коду заново.

## Проверено

- Node: **42/42**.
- Android JVM + Java-host: **40/40**.
- Windows: transport/TLS/discovery V2/firewall — PASS.
- Проверены protocol gate, очистка при старте/остановке, fail-closed cleanup, отзыв в roster, sessionId-reset, host ID migration.
- Codex: план + два read-only ревью. Первое выявило Critical/High по shutdown, session reset, protocol gate, identity и roster; часть исправлена. Финальный проход после всех правок не запускался — бюджет 3/3.

## Ограничения

- Идентичность устройства в этой версии — **TLS-защищённый bearer-токен**, а не отдельная CNG/Keystore-ключевая пара с challenge-response. Это следующий шаг; не используйте приложение в недоверенной сети.
- Roster не подписан криптографически; он хранится локально и передаётся только по TLS. Отзыв распространяется через roster, но не является кворумным.
- Discovery не подписан identity-ключом; подлинность соединения проверяется по TLS fingerprint, discovery — только подсказка адреса.
- Android crash-marker реализован, но проверен на JVM/сборке, не на физическом устройстве.
- Автоматического handoff и кворума нет: смена главного — ручная остановка и выбор нового устройства.
- Реальная матрица Windows↔Android, DHCP-смена IP, kill -9 и физический Android не проверялись.
