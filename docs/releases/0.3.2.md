# Рядом 0.3.2 — что нового

**Дата:** 19.11.2026  
**Статус:** выпущен  
**Тег:** [`v0.3.2`](https://github.com/Eugene-doc/ryadom/releases/tag/v0.3.2)  
**GitHub Release:** <https://github.com/Eugene-doc/ryadom/releases/tag/v0.3.2>

## Главное

0.3.2 — срочный патч входящих подключений на Windows. Протокол остаётся **3**; обновите обе платформы.

- **Диагностика входящих подключений.** Отчёт «Проверить брандмауэр и сеть» теперь показывает локальные адреса, категорию сети, профили брандмауэра Windows, активный сторонний брандмауэр и отсутствующие правила.
- **Сеть «Общедоступная».** Если домашняя сеть определяется как Public, приложение предлагает переключить её в «Частную» через UAC. В Public Windows/ESET по умолчанию блокируют входящие — это объясняет асимметрию «этот ПК подключается к ноутбуку, а ноутбук к нему нет».
- **ESET и другие сторонние брандмауэры.** Приложение больше не ограничивается предупреждением: показывает точные входящие правила TCP 4280 / UDP 42800, путь к приложению и может открыть окно ESET. Устаревшие записи Kaspersky без запущенной службы отфильтровываются.
- **Правила Windows.** Если брандмауэр Windows включён, можно установить корректные входящие правила для текущего EXE; они проверяются до и после установки.
- **Понятнее ошибка.** Вместо сухого «Нет ответа» при неудачном подключении показывается подсказка проверить TCP 4280/UDP 42800, профиль «Частная» и ESET/Happ.
- **Надёжнее self-check.** Локальный адрес распознаётся несколькими способами, чтобы исключить подключение к самому себе даже при необычном сетевом профиле.

## Почему ноутбук не подключался

На проблемном ПК сеть Ethernet имела категорию **Public**, а активным сетевым фильтром был **ESET Firewall**; профили Windows Firewall Public/Private были выключены, правила Ryadom отсутствовали. Исходящие соединения при этом работали, поэтому ПК мог подключаться к ноутбуку. Входящий TCP 4280 на ПК блокировался до приложения — это не ошибка TLS или сертификата.

После обновления на главном ПК откройте меню значка → **«Проверить брандмауэр и сеть»**:
1. Согласитесь сделать домашнюю сеть **«Частной»** (UAC).
2. В ESET откройте настройки брандмауэра и разрешите **Ryadom-Windows.exe** входящие **TCP 4280** и **UDP 42800** для доверенной/домашней сети.
3. Если Windows Firewall включён — установите предлагаемые правила.
4. Перезапустите Рядом и проверьте подключение с ноутбука.

Приложение не отключает ESET и не меняет его правила молча: это сторонний продукт безопасности, правило должно быть подтверждено в его окне.

## Совместимость и обновление

- **Протокол 3**, как в 0.3.0/0.3.1.
- **Windows 0.3.2.0**; для собственного окна нужен Microsoft Edge WebView2 Runtime.
- **Android 0.3.2, `versionCode 10`**; устанавливается поверх 0.3.1 с сохранением данных.

## Проверено

- Node 39/39.
- Android JVM + Java-host: адреса, TLS/TOFU, удаление/очистка, рестарт — `fail 0`.
- Windows: self-address detection, первый pin/probe, TLS/TOFU, firewall rule parser — PASS; диагностический `--firewall-check` на проблемном ПК показывает `Network: Ethernet=Public`, `ESET Файервол` и отсутствие правил.
- Сборки, подпись и хэши проверены.

## Ограничения

- Реальный ноутбук/Android и полная матрица Windows 10/11 не проверялись автоматически.
- Автоматически настраивается только категория сети и правила Windows Firewall; правило ESET добавляется пользователем в ESET.
- Если после «Частной» сети и правила ESET входящие всё ещё блокируются, проверьте Happ/VPN и изоляцию клиентов на роутере.
